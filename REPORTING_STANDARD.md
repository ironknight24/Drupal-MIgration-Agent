# Reporting Standard & Schema Specifications

## 1. Reporting Principles

All outputs generated by framework agents must satisfy three foundational requirements:
1. **Machine-Readable**: Every report begins with a standardized YAML frontmatter block containing metadata, component status, timestamps, and confidence ratings.
2. **Human-Auditable**: Content following the frontmatter must be clear, well-structured GitHub-flavored Markdown with tables, code snippets, and evidence citations.
3. **Deterministic & Timestamped**: Reports follow fixed naming conventions and must be reproducible from the recorded facts.

---

## 2. Standard Directory Organization

```
reports/
├── discovery/             # Audit reports: DISCOVERY-<DATE>.md
├── dependencies/          # Dependency graphs & sequencing: DEPENDENCIES-<DATE>.md
├── contrib/               # Contrib compatibility audits: CONTRIB-<MODULE>.md
├── custom-modules/        # Custom module migration plans & reports: MODULE-<NAME>.md
├── themes/                # Theme modernization reports: THEME-<NAME>.md
├── configuration/         # Configuration & CMI migration logs: CONFIG-<CATEGORY>.md
├── data/                  # Data migration mappings & ETL logs: DATA-<PIPELINE>.md
├── api-modernization/     # API refactoring logs & DI service mappings: API-<SCOPE>.md
├── testing/               # Automated test execution outputs: TEST-<SUITE>-<DATE>.md
├── validation/            # Side-by-side behavioral audits: VALIDATION-<COMPONENT>.md
├── blocked/               # Blocked tickets: BLOCKED-<COMPONENT>-<ID>.md
└── final/                 # Final comprehensive migration sign-off: FINAL-AUDIT.md
```

---

## 3. Mandatory Report YAML Frontmatter Schema

Every report generated in `reports/` MUST start with this structured frontmatter:

```yaml
---
report_id: "REP-MOD-EXAMPLE-001"
component: "example_module"
category: "custom_module" # discovery | dependency | contrib | custom_module | theme | config | data | test | validation | audit
agent: "custom-module"
created_at: "2026-09-18T19:00:00Z"
source_path: "drupal7/modules/custom/example"
target_path: "drupal/web/modules/custom/example"
status: "completed" # not_started | in_progress | completed | blocked | failed
evidence_summary:
  observed_facts: 12
  inferences: 3
  proposals: 2
  assumptions: 0
  verified_results: 4
---
```

## 4. Standard Blocked Item Schema (`reports/blocked/BLOCKED-XXX.md`)

When an agent encounters an impasse, it outputs a ticket formatted according to `templates/blocked-item.md`:

```yaml
---
ticket_id: "BLOCKED-MYMODULE-001"
severity: "HIGH" # LOW | MEDIUM | HIGH | CRITICAL | GLOBAL
type: "COMPONENT" # COMPONENT | GLOBAL
component: "my_module"
agent: "custom-module"
created_at: "2026-09-18T19:00:00Z"
status: "ACTIVE" # ACTIVE | RESOLVED
affected_dependents:
  - "dependent_module_a"
  - "dependent_module_b"
---
```

### Required Ticket Sections
1. **Summary of Impasse**: Concrete explanation of what halted progress.
2. **Environmental Context**: Exact source file, line number, or schema definition.
3. **Attempted Solutions**: Chronological record of approaches attempted and why each failed.
4. **Impact Assessment**: Direct impact on this component and downstream dependencies.
5. **Required Information / Action**: Specific action, missing specification, or credential required from a human engineer.

## 5. Standard Validation Matrix Schema (`reports/validation/`)

Every validation report must present the 12-dimensional comparison matrix:

| Dimension | D7 Expected / Observed Behavior | D10 Implemented Behavior | Verdict | Evidence / Command Reference |
|---|---|---|---|---|
| Functionality | Node publish triggers custom alert | EventSubscriber sends notification | `PASS` | `tests/src/Kernel/AlertTest.php` passed |
| Business Rules | Discount applied only to VIP role | VipDiscountService checks user role | `PASS` | Test case 3 assertEqual(20, $disc) |
| Permissions | `administer custom module` | Custom permission in `permissions.yml` | `PASS` | Anonymous gets 403, Admin gets 200 |
| Data Integrity | 1,450 records in `custom_table` | 1,450 records migrated to custom entity | `PASS` | Record count checksum verified |
| Relationships | Node author maps to D7 uid | Entity reference points to D10 User | `PASS` | Sample check on 50 nodes |
| Configuration | `variable_get('alert_threshold')` | `custom.settings:threshold` in CMI | `PASS` | Config export verified |
| Routes & URLs | `/custom/dashboard` | Route `custom.dashboard` in routing.yml | `PASS` | HTTP 200 OK |
| Forms | `custom_admin_form` with 4 fields | `FormBase` implementation with 4 fields | `PASS` | Form submit saves to config |
| Integrations | cURL call to payment gateway | Guzzle HTTP Client in payment service | `PASS` | Mock HTTP test passed |
| Output & Markup| `theme_custom_box()` markup | `custom-box.html.twig` with BEM classes | `PASS` | Rendered output matches DOM test |
| Workflows | Revision history preserved | D10 Node revisions populated | `PASS` | Revisions match D7 baseline |
| Performance | DB query execution < 15ms | Optimized query with proper index | `PASS` | Query log analysis verified |

**Permitted Verdicts**:
- `PASS`: Verifiable empirical proof documented.
- `PARTIAL`: Core behavior works, minor non-blocking issue flagged.
- `FAIL`: Behavior diverges or fails assertion.
- `BLOCKED`: Cannot be tested due to upstream block.
- `N/A`: Dimension not applicable to this component.
