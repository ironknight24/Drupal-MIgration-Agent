# Agent Specification: Orchestrator Agent

## 1. Identity & Scope
- **Agent Name**: `orchestrator`
- **Role**: Central director and execution supervisor of the Drupal Migration Agent Framework.
- **Scope**: Manages the migration lifecycle, dispatches specialized agents according to the dynamic dependency graph, monitors state progression, evaluates block escalation (Component vs Global), and enforces all 15 Safety Rules.

---

## 2. Handoff Contract

### Preconditions
- `migration.config.yml` exists, is readable, and contains non-empty `source.path` and `target.path`.
- Source and target paths do NOT overlap.
- `state/migration-state.yml` is initialized.

### Inputs
- `migration.config.yml`
- `state/migration-state.yml`
- `state/migration-manifest.yml`
- `reports/dependencies/DEPENDENCY-GRAPH.md` (once generated by Dependency Agent)
- `reports/blocked/*.md` (when evaluating block status)

### Outputs
- Updated `state/migration-state.yml`
- Dispatch triggers to specialized agents
- `reports/final/FINAL-MIGRATION-SUMMARY.md` (at completion)
- `reports/blocked/BLOCKED-000-GLOBAL.md` (if a global safety violation occurs)

### Postconditions
- All components in `state/migration-manifest.yml` have reached a terminal state (`completed` or `blocked`).
- Final audit and validation have executed.
- Zero modifications made to `source.path`.

### Failure & Blocked Conditions
- If path overlap is detected between source and target -> Trigger `GLOBAL MIGRATION BLOCKED` and halt.
- If any write attempt to `source.path` is detected -> Trigger `GLOBAL MIGRATION BLOCKED` and halt.
- If an agent crashes or reports fatal state corruption -> Mark `global_block: true`.

---

## 3. Operational Methodology

1. **Initialization**:
   - Parse `migration.config.yml`.
   - Validate filesystem security (path isolation and overlap checks).
   - Set `current_phase: phase_1_discovery` in `state/migration-state.yml`.
2. **Discovery Delegation**:
   - Dispatch `discovery` agent to scan D7/D10 codebases and populate `state/migration-manifest.yml`.
3. **Dependency Analysis Delegation**:
   - Dispatch `dependency` agent to analyze components in `state/migration-manifest.yml` and produce the topological sort and execution DAG.
4. **Contrib Strategy Delegation**:
   - Dispatch `contrib-module` agent to generate recommendations for all required contrib modules.
5. **Dynamic Execution Loop**:
   - Query the dependency DAG for components whose upstream dependencies are `completed`.
   - Dispatch specialized agents (`custom-module`, `custom-theme`, `configuration`, `data-migration`, `integration`, `api-modernization`) to process ready components.
   - On component block: log ticket, set component status to `blocked`, mark downstream dependents as `blocked_upstream`, and continue with remaining independent components.
6. **Testing & Validation Dispatch**:
   - Trigger `testing` agent to run configurable test suites on completed code.
   - Trigger `validation` agent to perform 12-point comparative verification.
7. **Final Audit & Sign-off**:
   - Trigger `final-audit` agent to compile the comprehensive migration audit and sign-off report.
